# 🛫 Travel Assistant — Архитектура системы

## 📋 Обзор проекта

Travel Assistant — это мультиагентная система помощи сотрудникам в организации командировок. Система использует:
- **RAG** (Retrieval Augmented Generation) для поиска правил политики
- **Мультиагентов** (Поисковик, Аналитик, Бронировщик)
- **Локальную LLM** (LM Studio) с возможностью переключения на OpenRouter
- **Векторную БД** (Chroma InMemory) ц

## 🔄 RAG Flow (Retrieval Augmented Generation)

### Пайплайн поиска релевантных документов

```
┌─────────────┐
│   Запрос    │  ← Пользователь задаёт вопрос
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Чанкинг    │  ← Разбивка текста на куски (chunk_size=500, overlap=50)
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Эмбеддинг   │  ← Преобразование текста в векторы (768 размерность)
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Поиск      │  ← top-k (k=3) ближайших чанков по cosine-сходству
└──────┬──────┘
       │
       ▼
┌─────────────┐
│   Рeranker  │  ← Кросс-энкодер для улучшения релевантности (опционально)
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  Top-n      │  ← Возврат n самых релевантных кусков текста
└─────────────┘
```

### Детали компонентов RAG

#### 1. Чанкинг (Chunking)
```python
CharacterTextSplitter(
    separator="\n",           # Разделитель: новые строки
    chunk_size=500,          # Размер чанка: 500 символов
    chunk_overlap=50,        # Нахлест: 50 символов
    length_function=len      # Длина по количеству символов
)
```

**Почему:** Маленькие чанки дают более точный поиск, нахлест сохраняет контекст.

#### 2. Эмбеддинг (Embedding)
```python
HuggingFaceEmbeddings(
    model_name="text-embedding-qwen3-embedding-0.6b",
    model_kwargs={'device': 'cpu'},
    encode_kwargs={'normalize_embeddings': True}  # Cosine-сходство = 1 для идентичных текстов
)
```

**Векторная размерность:** 768  
**Нормализация:** Да (векторы лежат на поверхности единичной сферы)

#### 3. Векторное хранилище
```python
Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    collection_name="travel_assistant",
    persist_directory=":memory:"  # InMemory — не сохраняем на диск
)
```

**Metadatas:**
- `source`: "policy" (документы политики) или конкретные поля билета

#### 4. Поиск (Similarity Search)
```python
vectorstore.similarity_search(query, k=3, filter={"source": "policy"})
```

**k=3** — берём 3 ближайших документа  
**filter** — опциональная фильтрация по метаданным

#### 5. Рeranker (опционально)
Используется кросс-энкодер (CrossEncoder) для более точной оценки релевантности:
```python
scores = reranker.predict([(query, text) for text in candidate_texts])
```

## 🤖 Агенты системы

### 1. PolicyExpert (Агент-эксперт по политикам)

**Назначение:** Поиск релевантных правил политики компании для командировок.

**Входные данные:**
- `user_query` — исходный запрос пользователя

**Логика:**
1. Принимает запрос пользователя
2. Использует RAG для поиска релевантных кусков документов из политики
3. Возвращает найденные правила в контексте (`policy_context`)

**Выходные данные:**
- `policy_context`: текст найденных правил политики

**Код:**
```python
relevant_docs = self.vectorstore.similarity_search(
    query, k=3,
    filter={"source": "policy"}  # фильтруем только политику
)
policy_context = "\n\n".join([doc.page_content for doc in relevant_docs])
```

---

### 2. TicketSearcher (Агент-поисковик билетов)

**Назначение:** Поиск авиабилетов из CSV-файла по маршруту и дате.

**Входные данные:**
- `user_query` — запрос пользователя

**Логика (rule-based экстракция):**
```python
# Извлечение параметров из запроса
departure = "Москва" if any(w in query for w in ["москв", "из москвы"]) else None
arrival = "Санкт-Петербург" if any(w in query for w in ["питер", "петербург"])
# ... другие города ...

# Фильтрация билетов по городам и дате
filtered = tickets_df[
    (tickets_df["departure_city"] == params["departure"]) &
    (tickets_df["arrival_city"] == params["arrival"])
]
```

**Выходные данные:**
- `extracted_params`: {departure, arrival, date}
- `tickets`: список найденных билетов из CSV

---

### 3. BudgetAnalyst (Агент-аналитик бюджета)

**Назначение:** Проверка найденных билетов на соответствие бюджетным ограничениям.

**Входные данные:**
- `tickets` — найденные билеты
- `policy_context` — правила политики

**Логика:**
```python
DEFAULT_LIMITS = {
    "max_ticket_price": 50000,       # Макс. стоимость билета
    "daily_per_diet_russia": 2500,   # Суточные по России
    "daily_per_diet_abroad": 5000,   # Суточные за границей
    "max_hotel_price_russia": 8000,  # Макс. стоимость отеля в РФ
    "max_hotel_price_abroad": 12000  # Макс. стоимость отеля за рубежом
}

# Проверка первого билета (можно проверить все)
ticket = tickets[0]
budget_result = {
    "ticket_price": ticket["price"],
    "max_limit": DEFAULT_LIMITS["max_ticket_price"],
    "within_budget": ticket["price"] <= DEFAULT_LIMITS["max_ticket_price"],
    "message": f"Билет за {ticket['price']} руб. {'входит' if within_budget else 'превышает'} лимит"
}
```

**Выходные данные:**
- `budget_check`: результат проверки бюджета

---

### 4. HotelBooker (Агент-бронировщик отелей)

**Назначение:** Рекомендация отелей, соответствующих политике и бюджету.

**Входные данные:**
- `budget_check` — результат проверки бюджета

**Логика:**
```python
# База отелей (пример)
hotels = {
    "Москва": [
        {"name": "Hotel A", "price": 5000, "has_wifi": True, "has_breakfast": True},
        {"name": "Hotel B", "price": 7000, "has_wifi": True, "has_breakfast": False},
    ],
    "Санкт-Петербург": [...],
}

# Фильтруем по бюджету и Wi-Fi
budgeted = [h for h in available_hotels 
            if h["price"] <= 8000 and h["has_wifi"]]

# Выбираем самый дешёвый
best_hotel = min(budgeted, key=lambda x: x["price"])
```

**Выходные данные:**
- `best_hotel`: рекомендуемый отель
- `final_answer`: итоговый ответ пользователю

## 🎯 Оркестратор (TravelAgentManager)

### StateGraph на LangGraph

```python
class AgentState(TypedDict):
    """Состояние, передаваемое между агентами"""
    user_query: str                # исходный запрос
    extracted_params: dict         # извлечённые параметры
    policy_context: str            # RAG-результат
    tickets: list                  # найденные билеты
    budget_check: dict             # результат проверки бюджета
    final_answer: str              # итоговый ответ
    next_agent: str                # следующий агент
    logs: list                     # для отладки
```

### Создание графа

```python
workflow = StateGraph(AgentState)

# Добавляем узлы (агенты)
workflow.add_node("PolicyExpert", self.policy_expert.invoke)
workflow.add_node("TicketSearcher", self.ticket_searcher.invoke)
workflow.add_node("BudgetAnalyst", self.budget_analyst.invoke)
workflow.add_node("HotelBooker", self.hotel_booker.invoke)

# Условные рёбра
workflow.add_conditional_edges(
    "PolicyExpert",
    lambda x: x.get("next_agent", "TicketSearcher")
)
```

### Точка входа

```python
workflow.set_entry_point("PolicyExpert")
```

## 📝 Вклад данных

### Роль PolicyExpert

- **Поиск правил:** Использует RAG для поиска релевантных правил политики
- **Контекст:** Передаёт найденные правила следующим агентам
- **Фильтрация:** Ограничивает поиск документами с `source="policy"`

### Роль TicketSearcher

- **Парсинг CSV:** Читает `data/tickets.csv` и фильтрует по городам и дате
- **Экстракция:** Извлекает параметры из запроса (rule-based)
- **Метаданные:** Добавляет метаданные к билетам для RAG

### Роль BudgetAnalyst

- **Проверка:** Сравнивает стоимость билета с лимитами из политики
- **Сообщения:** Формирует понятные сообщения о бюджетных ограничениях
- **Адаптивность:** Может использовать RAG для извлечения лимитов динамически

### Роль HotelBooker

- **Рекомендации:** Фильтрует отели по бюджету и удобствам (Wi-Fi, завтрак)
- **Сортировка:** Выбирает самый дешёвый подходящий вариант
